# 1.2 · 真正的歌曲分类与 AE 加载修正

## 用户提供的现场证据

截图显示 `AE 脚本加载失败：SyntaxError: 应为: ) line 369`。本机已安装 1.1 的打包 `host.jsx` 第 369 行为 `safeName` 文件名过滤，使用了含未转义 `/` 的正则字符类。标准 ES3 解析器接受这种写法，ExtendScript 在此行报错；此前只做普通 JS 静态解析未能捕获这一差异。

修改为逐字符检查非法文件名字符；构建器以 Acorn 的正则 token 为边界，将正则字符类内的裸斜线转义。对已安装 1.1 文件作静态兼容扫描，发现 1 处该形式，与截图的源位置相符。未启动 AE，不把静态扫描当成 AE 加载成功的实测证明。

## 分类来源和行为

实际读取旧 PV 项目的 `JIZURA-AE/upstream/src/11r_song_profiles.js`。使用同一组六个名称：慢歌抒情、极简叙事、流行轻快、摇滚燃曲、电子舞曲、电影感。

新模型 `songProfile` 控制排版候选、入场/出场候选、停留动作、速度、强度上限、字旁元素候选与数量上限。没有按摆放位置定义歌曲分类。完全随机、自建集合继续在主下拉框内；64 个排版作为分类内的候选及可手动选择的预设。

慢歌/电影感保留参考视频的大字与小字关系、局部高亮、淡入和留白；燃曲/电子的节奏动作限制在文字及字旁元素上，保持 MAD/AMV 透明叠加用途。

1.1 的 16 个视觉名称通过兼容映射迁移到六分类。旧收藏混搭入口移到预设库的“只看收藏”，收藏数据保留；自建风格保持原预设集合，可编辑或删除。

旧方案中的固定单排版、未绑定视觉名称的收藏混搭，迁移为方案内的自选集合，保留原先选择的排版池。切回完全随机时重新抽取自由参数，恢复自动字旁元素，避免沿用极简分类的零装饰限制。
