# 1.4.3：预渲染模板名称与失败清理

## 本地证据

2026-10-04 的桥接日志中，错误发生在 `preRender` 调用，分别为“? Alpha 不是有效的模板名称”和“??? 不是有效的模板名称”。截图的行 1623 是旧版打包宿主重新抛出异常的位置，真实调用为 `OutputModule.applyTemplate`。

本机 AE 25.6 的输出模块设置仍包含“无损”“高品质”“具有 Alpha 的高品质”“仅 Alpha”等中文名称。名称在当前链路中出现问号损坏；旧版将面板返回的显示名称直接传给 `applyTemplate`，并只在成功后删除临时队列项。确切的 AE 原生编码边界未通过实际运行确认。

## 修改

- 原始模板名称保留在 AE 内，面板仅传 ASCII 选择编号和本次选择标识。
- 宿主响应 JSON、面板参数和 ExtendScript JSON 解析均将非 ASCII 字符转为 Unicode 转义，保留中文、特殊符号及补充平面字符。
- 项目、合成、模板列表或选择标识失效时停止并提示重新选择，不随机替换模板。
- 增加“当前 AE 默认输出设置”，不调用名称模板，使用新建队列项的默认输出模块。
- 应用模板后重新获取输出模块对象，避免后续读取失效引用。
- 默认优先选择带颜色与 Alpha 的模板，排除“仅 Alpha”的遮罩输出和图像序列。
- 失败、取消和成功后均清理本次临时队列项；原有队列勾选恢复。不会扫描或删除用户已有队列项。
- 图像序列、音频和未知格式不再根据默认文件后缀误当作 mp4；渲染后缺少文件时不尝试导入。
- 错误在面板状态栏显示具体阶段；失败后可直接重新打开预渲染，避免停留在“正在预渲染”。

## 自检

`node scripts/check-prerender.mjs`：21 项，调用实际桥接代码及编译后的宿主代码，模拟 AE API。

覆盖中文名称经过有损桥接、JSON 参数编码、默认输出、模板应用失败、输出模块引用更新、项目/模板/选择变化、重复提交、取消与失败清理、原有队列勾选恢复、视频导入、输出格式识别及文件缺失。

`node scripts/check-prerender-panel.mjs`：4 项，在独立无界面浏览器中驱动真实面板按钮、桥接代码和宿主脚本，模拟 AE API。覆盖中文选项、默认输出、失败状态恢复及重新选择后成功。

报告位于 `reference/1.4.3-selfcheck/`。首次 11 项检查中旧实现通过 4 项；修复后扩大为 21 项，全部通过。另执行 JavaScript / ES3 静态解析、NSIS 构建与已安装文件 SHA-256 核对。

没有启动、关闭或控制用户 AE，也没有真实渲染、访问翻译 API 或修改 AE 首选项。模拟检查不等同于 AE 原生运行验证。

## 更新后使用

关闭并重新打开映词面板，顶部显示 1.4.3。打开要预渲染的合成后点“预渲染”，选择视频模板或“当前 AE 默认输出设置”。透明叠加需带 Alpha 的 QuickTime/AVI 设置。视频完成后依旧自动导入 AE 项目并创建可直接调用的视频合成。
