# 1.5.3：直接导出面板歌词视频

## 已记录的 AE 行为

- AE 25.6.4 的共享 ExtendScript 引擎使用 `CP1252`，Windows 的 ANSI 代码页为 `936`。
- 原先中文输出模板名称进入原生 `applyTemplate` 后变为 `?? Alpha ????`。
- 临时改为 UTF-8 后，AE 报出的名称变成 `鍏锋湁 Alpha 鐨勯珮鍝佽川`。将 `具有 Alpha 的高品质` 编成 UTF-8 后按 CP936 解码，可以逐字复现这一结果。
- 改为 CP936 后，用户实际操作通过了模板应用，但随后的渲染仍失败：输出目录中的中文被变成问号。原因是旧实现仅在应用模板时切换编码，在设置输出文件之前已恢复 CP1252。
- 将系统编码保护扩大到整个预渲染流程后，实际日志中的中文目录及文件名已正确。AE 根据输出模板将 `.mp4` 调整为 `.mov`，此前完整路径比较把这一正常行为误判为路径损坏。

## 当前修改

- 按用户澄清，预渲染直接逐帧绘制面板当前方案，独立于“生成 AE 动态歌词”；不读取当前 AE 合成、不调用 AE 渲染队列。
- 支持 MOV（PNG 无损画面，可保留 Alpha）与 MP4（WebCodecs H.264）；视频边编码边写入磁盘，完成后自动导入 AE 项目并创建可调用合成。
- 视频背景直接沿用预览中的选择，包括载入的画面；导出窗口不再重复设置背景。预览为透明底时使用 MOV，选择 MP4 则提示先修改预览底图。
- 支持小数帧率。MP4 将整数轨道时间基与实际帧率分开设置，避免封装器拒绝 23.997 等小数。
- 可包含已载入的音乐；MOV 使用 PCM，MP4 使用 AAC。所选格式编码能力不足时提示原因，不悄悄换格式或丢掉音乐。
- 保留歌词原始时间，导入后定位首句可见位置。全片无可见歌词时拒绝导出，取消时移除未完成文件；导入失败保留完整视频。

## 原生调用兼容处理

- Windows 从系统的 `ACP` 注册表值读取原生调用代码页，65001 使用 UTF-8；macOS 使用 UTF-8。
- 模板应用、输出路径赋值、渲染及视频导入共用同一个编码保护范围，成功、取消或异常后恢复共享引擎原编码。
- 输出路径写入后立即读回，比较目录和文件名主体；接受 AE 按模板选择 `.mov`、`.avi`、`.mp4` 后缀，后续渲染结果检查、视频导入和失败文件位置均使用实际路径。目录、文件名主体变化或非视频后缀仍会在渲染前停止并记录两者。
- 继续使用用户选定的输出模板，不因失败切换模板或改变 Alpha 配置。
- 宿主与面板除版本号外还核对修订标识，避免同版本补丁仍使用内存中的旧脚本。
- 本地桥接日志记录实际宿主修订、调用编码、出错阶段及成功导入事件。

## 验证范围

回归覆盖 CP1252 问号损坏、UTF-8/CP936 乱码、中文目录与文件名、原生编码恢复、失败清理、输出路径读回、AE 视频后缀调整后的导入、目录及文件名变化拦截、非视频后缀拦截、默认输出选项和宿主缓存。

旧的 `native-output-acp-4` 曾返回成功导入，但用户指出输出为空。后续逐帧检查确认 1560 帧 Alpha 最大值全部为零：文件可解码不代表歌词输出正确。根因是旧流程渲染了当前空合成，违背网页直接导出的需求。该结果不能作为新流程验证通过的证据。

新检查通过真实面板事件绘制和编码视频，再检查视频样本中的可见歌词及透明像素；AE 导入 API 单独模拟。另用独立解码器检查实际 MOV/MP4 文件。用户已确认新流程正常导出并导入歌词视频，又反馈 MP4 小数帧率被封装器拒绝，本次继续修正时间基。开发过程没有启动或操控用户 AE。
