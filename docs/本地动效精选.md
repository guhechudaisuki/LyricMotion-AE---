## 面板接入

- 本地预设页默认显示“精选动态库”，按以上动作分类筛选；这些是素材分类，顶部歌曲风格分类继续保持原有逻辑。
- GIF 配对忽略 FFX 文件名前的 `IN_` / `OUT_` / `MID_`，同一进入/离开配对共用原包完整演示。
- 工程卡片使用工程内某个 GIF 示意，标记“工程合集”；通过“导入工程并选择合成”拿到 AE 实际合成列表，不推测或伪造 `compName`。
- 9 个 Clean 文字工程标记为“文字模板 · 手动编辑”。导入后选择 AE 返回的真实合成 ID，通过“打开文字模板”在 AE 中打开合成，由用户替换歌词与调整时间；不把模板中的原文缩成字旁素材。
- “用本组建立风格”过滤上述需手动编辑的文字 AEP，然后调用 `hooks.createStyle(records, name)`，打开主界面的自选集合流程，允许继续增减选择。纯文字模板组只提示手动使用方法，不打开空风格对话框；混合结果会提示排除数量。
- 字旁 AEP 继续先选真实合成，再使用“加入当前合成”；切换回字旁素材时会恢复按钮和滤色选项。
- 独立加载 `curated-motion.js`，随后合并完整 `local-catalog.js`。后加载的完整索引与手动扫描都保留精选分类、预览和依赖信息。

## 检查范围与限制

生成时对 523 个资产路径和 520 个预览路径执行文件存在性检查，缺失数为 0；FFX 文件还实际读取了二进制内容。**503 个 FFX 均含 `Pseudo/` 控件标记**，可能依赖原包自定义控件、表达式、字体或原作者脚本，因此卡片提示尚未在 AE 中逐项验证。这不是“检测到缺失插件”的结论。

没有启动 AE，没有添加或运行测试，也没有声称原包动效能不经调整就完整适配全部中文字体。特别是 Words 类依赖分词，连续中文需按期望的节奏分词；FFX 的进入和离开文件应合理配对。

第三方 FFX、AEP、GIF、字体和素材没有复制进安装器。面板保存本机路径，移动源库后需重新扫描或重新生成清单。带水印的 GIF 只用来挑选，不参与成片。

重新生成命令：

```powershell
node scripts/curate-motion.mjs
```
